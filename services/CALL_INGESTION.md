# Call inbox, transcript recovery and Claude analysis

The receiver runs on Maincloud **`hackutd-richardson` only**. `npm run voice` (or `npm run voice:inbox`) now starts `scripts/call-inbox.ts`, which receives signed ElevenLabs webhooks, reconciles provider history, archives transcripts, and processes Claude analysis. It does not start the survey, callback or messaging runners. The existing three-number allowlist and outbound-call approval requirements still apply to any separate dial command. No writes to `hackutd-535md` are allowed.

For an explicitly triggered one-phone judge demonstration, use [OUTBOUND_DEMO.md](OUTBOUND_DEMO.md). Its `demo:outbound` CLI places at most one call per named attempt; this receiving service stays receive-only. The currently verified phone connection is still rejected with SIP 603, as documented in that runbook.

## Data available to the portal

- Public `call_record`, keyed by ElevenLabs `provider_id`, is the complete provider call history for the configured agent. It includes inbound/outbound direction, processing/done/failed status, masked caller label, actual start/duration, ordered `turns` (`agent`/`resident`), transcript revision, and optional `call_id`/`household_id` links. Unknown callers and failed attempts remain visible without inventing a household or location.
- Known callers also receive an ordinary `call` row and `transcript_line` rows in the same database transaction. Existing execution jobs and synthetic fixtures remain intact. Replays of a finalized provider conversation add no duplicate rows or analysis work.
- Public `call_analysis`, keyed by the same provider ID, reports `pending`, `analyzing`, `ready`, `failed`, or `no_transcript`. `result_json` contains the summary, advisory priority/reason, facts with exact transcript quotes/turn indexes, unknowns, and suggested next steps. `model` records the actual Claude model. Empty failed calls are logged with `no_transcript`, without inventing transcript text or calling Claude.

The portal subscribes to both tables. The **Calls** sidebar view shows every provider call, its original transcript and Claude analysis. Linked household case files also show the latest analysis. Dispatcher-only `retryCallAnalysis({ providerId })` retries a failed analysis; the worker also retries automatically. AI findings do not rewrite household needs, change dispatch priority, assign a responder or send a message. A dispatcher reviews the transcript and confirms the facts.

## Ingestion and recovery

`POST /elevenlabs/webhook` verifies the provider HMAC and persists the complete event under `services/.spacetime/call-inbox/` with a private file, atomic rename and fsync before returning HTTP 200. It does not wait for SpacetimeDB or Claude. Failed jobs stay on disk; one failing event does not block the rest. A full verified payload can recover the conversation even if ElevenLabs' read API is unavailable.

Every 30 seconds the worker pages through the configured agent's provider history and imports missing/unfinished records. This recovers webhook delivery failures and service downtime without another phone call. Transcripts commit before analysis begins. A dropped database connection reconnects; database calls have a 10-second deadline. Analysis jobs live in the database, use 120-second claims, reject stale workers, and retry failed attempts with a delay up to 15 minutes. Completed analysis is not regenerated by an event replay or receiver restart.

Call linkage uses provider-supplied job IDs or a known household's phone. In this isolated demo, the single selected resident from `demoContacts(CONTACT_ALLOWLIST)` maps to the existing `demo-houston-anish` alias without placing a real number in the synthetic fixture. Other unknown callers remain unlinked in Calls; absence of the demo mapping never prevents archival. Caller identity and location are never inferred by Claude.

Service-only reducers are `recordProviderCall`, `claimCallAnalysis`, and `finishCallAnalysis`. `recordProviderCall` writes the archive, linked call/transcript and pending analysis atomically. Existing reducer signatures and table definitions are preserved. Claude output is validated in the service and database; every cited quote must exist at its exact transcript turn.

## Running and checking

Use `.env` for `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID`, `ELEVENLABS_WEBHOOK_SECRET`, `VOICE_PUBLIC_URL`, `VOICE_PORT` and `ANTHROPIC_API_KEY`. `CALL_ANALYSIS_MODEL` defaults to `claude-haiku-4-5`. The database target is pinned to the demo; the root `.env`'s operational `SPACETIME_DATABASE` is deliberately ignored by this receiver. Supply an existing granted `SPACETIME_DEMO_SERVICE_TOKEN`, or use the private service token already persisted in `.spacetime/demo-auth.json`. No identities or grants are created.

```sh
cd services
npm run voice                  # receive/archive/analyze; no outbound runners
npm run voice:inbox -- --once  # one reconciliation/analysis pass without opening an HTTP listener
```

The existing public Cloudflare tunnel must point to port 8080. `GET /capabilities` should report `database: "hackutd-richardson"`, `transcriptIngestion: true`, `claudeAnalysis: true`, and `outboundEnabled: false`. The workspace webhook has retries enabled; its destination and signing secret are preserved. Ingestion failures remain recoverable through the provider-history reconciliation even if a webhook retry is exhausted. Provider transcript retention still determines which historical conversations can be recovered after a prolonged outage.

The local portal `.env` now selects `VITE_SPACETIME_DATABASE=hackutd-richardson`. Other deployments must select that same database to see this demo. Do not put service or Anthropic credentials in `VITE_*` variables.

The running receiver's PID and log are `.spacetime/call-inbox.pid` and `.spacetime/call-inbox.log` at the repository root. Start only one receiver on port 8080; the provider reconciliation and database analysis claims remain idempotent across restarts. The tunnel is a separate existing process and must remain reachable. If the machine or receiver is stopped, the next start reconciles retained provider history.
